# Build My Player

Implemented 1 November 2026. Player Space has a Build My Player destination (`#builder`) linked from Home and More. A player saves one editable look. New looks start with a plain sports bra and full-coverage athletic briefs, then offer models, skin, face, eyes, build, four hair types/five colours, football/casual clothes, boots and accessories. All base art depicts generic fictional adult athletes; no identification photograph is used.

The wardrobe includes the STAR top, Arsenal and Chelsea home outfit interpretations from the existing approved squad references, plain T-shirts, hoodies, shorts, leggings and tracksuit bottoms. The two gold items reuse permanent coach-badge cosmetic unlocks. All seventeen Boot Locker pairs use their existing server-issued entitlements. Starter boots are generic and free.

A dressed saved look can be chosen on the player card and added once to any outfield squad slot, in either team size. It may captain the squad. Existing rosters and goalkeeper rules remain intact. It does not replace the home hero. A top and outer bottoms are required for card/squad display. Private identification photos, card photos, coaching records, achievements and account links are separate.

`player_space_profiles.builder_look` holds a strict cosmetic JSON object and `builder_on_card` holds the card preference. Existing family/player RLS remains unchanged. Column grants are explicit. A security-invoker trigger checks keys, value types, catalogues, existing boot/gold entitlements and the dressed-display rule. The squad trigger accepts the reserved `my-player` identity only with that player's own saved dressed look. Both triggers take the same transaction lock to serialize concurrent wardrobe/squad changes. Saves only show success after the existing profile/squad write returns. Failed saves retain drafts; leaving uses the existing draft guard. No private drafts are put into local storage.

Artwork uses built-in image_gen: transparent two-view illustrated adult sprite sheets, exported without stretching as 460×1024 WebP layers under `public/player-space/builder/`. Canvas composes the same layers on the editor, card and pitch; it recolours skin/hair and adds local eye, freckles and accessory details. Fit and boot appearance are illustrative estimates, not measured body data. Official STAR branding is composited from the existing logo asset.

Prompt set: generate a generic adult athlete matching the polished shaded sports-game squad illustration, front and back, full body, neutral stance, bald head, plain charcoal sports bra/full-coverage athletic briefs, transparent outside silhouettes; edit the same two-view sheet separately into the STAR, Arsenal, Chelsea, hoodie/trousers, white T-shirt and leggings outfits; edit four separate matching hair sheets for a wavy ponytail, curly bob, coily puff and braided bun. Outfit edits preserve pose/canvas/body landmarks; hair edits keep the hair above shoulders. Source references: existing `hero-player-star-kit.webp`, squad `fox.webp` and `walsh.webp`. No user/player data was submitted for artwork.

Validation: TypeScript and production build; 39 focused builder/collections/learning/activity checks; rendered artwork inspection; authenticated rollback-only `supabase/tests/build_my_player_rls.sql` verifies malformed/unknown JSON rejection, locked item rejection, all seventeen earned boots, gold unlocks, private saving, linked-player access, cross-family isolation, self placement/captain/uniqueness and both squad sizes. No usability testing.
