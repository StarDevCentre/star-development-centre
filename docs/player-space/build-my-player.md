# Build My Player

Implemented 1 November 2026. Player Space has a Build My Player destination (`#builder`) linked from Home and More. A player saves one editable look. New looks start with a plain sports bra and full-coverage athletic briefs, then offer models, skin, face, eyes, build, four hair types/five colours, football/casual clothes, boots and accessories. All base art depicts generic fictional adult athletes; no identification photograph is used.

The wardrobe includes the STAR top, 22 approved branded sportswear/casual additions and 26 illustrated 2026/27 women's home kits (14 WSL, 12 WSL2). White Fox Offstage hoodies are Shadow and Glacier Grey, selected from its official bestselling lounge range. Each club's shirt, shorts and socks can be selected separately or together. Search and clothing-style filters keep the catalogue manageable. The two gold items reuse permanent coach-badge cosmetic unlocks. All seventeen Boot Locker pairs use their existing server-issued entitlements. Starter boots are generic and free.

Durham, Sunderland and Watford explicitly show launch versions with blank principal-sponsor areas: current women's match sponsors could not be verified consistently. Other kits reproduce the researched public shirt/retail references as fan illustrations, not exact match-issued replicas. Everton uses its white home-replica shorts. Preserve these distinctions when updating sponsors; do not copy men's sponsors to women's shirts without evidence.

A dressed saved look can be chosen on the player card and added once to any outfield squad slot, in either team size. It may captain the squad. Existing rosters and goalkeeper rules remain intact. It does not replace the home hero. A top and outer bottoms are required for card/squad display. Private identification photos, card photos, coaching records, achievements and account links are separate.

`player_space_profiles.builder_look` holds a strict cosmetic JSON object and `builder_on_card` holds the card preference. Existing family/player RLS remains unchanged. Column grants are explicit. A security-invoker trigger checks keys, value types, catalogues, existing boot/gold entitlements and the dressed-display rule. The squad trigger accepts the reserved `my-player` identity only with that player's own saved dressed look. Both triggers take the same transaction lock to serialize concurrent wardrobe/squad changes. Saves only show success after the existing profile/squad write returns. Failed saves retain drafts; leaving uses the existing draft guard. No private drafts are put into local storage.

Artwork uses built-in image_gen: transparent two-view illustrated adult sprite sheets, exported without stretching as 460×1024 WebP layers under `public/player-space/builder/`. Canvas composes the same layers on the editor, card and pitch; it recolours skin/hair and adds local eye, freckles and accessory details. Fit and boot appearance are illustrative estimates, not measured body data. Official STAR branding is composited from the existing logo asset.

Prompt set: generate a generic adult athlete matching the polished shaded sports-game squad illustration, front and back, full body, neutral stance, bald head, plain charcoal sports bra/full-coverage athletic briefs, transparent outside silhouettes; edit the same two-view sheet separately into the STAR, Arsenal, Chelsea, hoodie/trousers, white T-shirt and leggings outfits; edit four separate matching hair sheets for a wavy ponytail, curly bob, coily puff and braided bun. Outfit edits preserve pose/canvas/body landmarks; hair edits keep the hair above shoulders. Source references: existing `hero-player-star-kit.webp`, squad `fox.webp` and `walsh.webp`. No user/player data was submitted for artwork.

Validation: TypeScript and production build; 39 focused builder/collections/learning/activity checks; rendered artwork inspection; authenticated rollback-only `supabase/tests/build_my_player_rls.sql` verifies malformed/unknown JSON rejection, locked item rejection, all seventeen earned boots, gold unlocks, private saving, linked-player access, cross-family isolation, self placement/captain/uniqueness and both squad sizes. No usability testing.

## Single teenage template, batch one — 1 November 2026

The owner requested one slim, teenage-looking character and removal of other models, followed by small fitting batches. The editor has no Models destination, preset picker or build selector. `builderLook` normalises every legacy build to slim; the renderer has no build scaling. Old enum values remain accepted by the server for compatibility, without creating additional visible models. No database migration or player-row rewrite is needed.

New built-in image_gen artwork depicts a fictional 16-year-old in a plain crew-neck training T-shirt, loose mid-thigh football shorts, ankle socks and starter boots. Natural slim proportions and a youthful face replace the earlier adult athlete template. The same fully clothed character supplies both views. The hoodie is a precise edit of that sheet, with the same wrists, hips, legs and feet. The source sheets are 1536x1024. Fixed crops at x=222 and x=854, width=460, height=1024 preserve the shared coordinates; no bounding-box garment scaling is used. `scripts/export-builder-template.cjs` documents the export. Four versioned transparent WebPs live in `public/player-space/builder/v2/`.

Batch one supports navy/white T-shirts, navy/gold hoodies, navy shorts, white/navy/black/red ankle socks and the starter boots. Gold still requires its existing coach reward. Explicit upper-garment coverage replaces the covered source pixels before the aligned hoodie is drawn, so the old arms/sleeves cannot show through. Knees, waist, hands and footwear share the template. Hair colours, skin tones and accessories remain editable. The ponytail is the first fitted hairstyle; other styles are marked for refitting. The fixed face preserves saved face/eye fields for compatibility; only implemented appearance controls are exposed.

`lib/builderFit.ts` records the completed batch. Pending clothing, kit parts, hairstyles and earned boots remain in the catalogue with a Being fitted label and cannot be selected yet. No earned entitlement is removed. Existing saved IDs are preserved; pending saved items render the corresponding training-template fallback and the editor explains this. Saving is blocked until all selected items have fitted artwork. Reset restores the saved choices. Existing cards/squads use the same renderer; their accessible image description identifies the fallback. New drafts start in the complete fitted training outfit. This staged availability must be lifted per item as each batch passes artwork inspection; do not enable old adult sprites on the new body.
