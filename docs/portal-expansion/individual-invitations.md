# Individual school and club invitations

Staff Portal → Schools & clubs → Access & players now sends a personal invitation email. New/unaccepted invitations can be resent; a successful SMTP submission, a failure and acceptance are recorded separately. Resend renews the 14-day organisation approval window. Supabase Auth owns the shorter-lived, single-use email security token. No tokens or passwords are stored in organisation tables or application logs.

New accounts use Auth inviteUserByEmail, verify their email by opening the invitation and choose a password in the organisation portal. Existing confirmed accounts receive a native one-time sign-in email and retain their password. The user-editable organisation_password_setup flag controls presentation only, never authorization; verified auth.users email plus active organisation membership remain authoritative. The existing Staff Portal fallback routes external organisation accounts to their own portal if Auth uses the configured Site URL instead of the requested redirect.

Sending is implemented by the organisation-invitation Edge Function. It validates the caller with Auth.getUser, then prepares the invitation through a verified STAR-manager-only RPC. Admin keys are supplied by the Edge runtime and never sent to the browser. The existing custom SMTP configuration sends native Auth invitations/sign-in emails; no new environment variable or additional email provider key is needed. Keep the organisation portal URL allowed in Auth redirect configuration for a direct arrival. An accepted account can be revoked/restored without resending or resetting its password. Revoked/paused memberships cannot open organisation records even if an old email link authenticates the account.

The database serialises each manager's invitation preparation, enforces a recipient cooldown of 60 seconds and limits 20 distinct invitation attempts per manager over five minutes. Status writes require service_role and the current attempt ID, preventing browser-forged success or stale delivery results. A network interruption can leave a pending status; refresh and resend after the cooldown rather than assuming delivery.
