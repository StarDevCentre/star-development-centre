# Schools and clubs inbox

Organisation Portal → Inbox supports general conversations and parent-approved player conversations. Staff Portal → Inbox → Schools & clubs brings every active organisation together, with subject/organisation search, unread filters and per-person read positions. Staff Home and organisation Overview show unread summaries. Email links open the appropriate inbox after sign-in; people with several organisations choose their organisation first.

Only active, accepted, verified organisation members and active STAR owners/managers have access. Player topics additionally require a current guardian-player relationship and sharing approval on every server operation. Revocation, changed invitation email, organisation pause and withdrawn parent consent also suppress pending email delivery. Generic organisation topics must not contain player-specific details; use the selected player connection. Existing family communication permissions and delivery behaviour are unchanged.

New selected feedback and observations share a player conversation. New coaching requests, request responses/status changes and referral responses/status changes enter contextual threads. Existing records are not backfilled or emailed. New users can read permitted history but receive notifications only for updates sent while they are accepted members. Sending users do not receive their own alerts. Read state is personal; opening one colleague's inbox does not clear another colleague's notifications.

The new private tables have RLS and deny direct client access. Public invoker RPCs delegate to checked private functions. Message requests use client UUIDs to prevent duplicate threads/replies on a retry; per-sender throttling caps manual messages at twenty a minute. Conversation history loads the latest hundred messages, with earlier-message pagination. Messages have no client edit/delete capability. Removing a player connection removes its associated inbox history through the existing privacy boundary.

## Email operations

`/api/organisation-alerts` runs only in production. A dedicated 256-bit credential is held in Supabase Vault (`organisation_email_worker_secret`) and the sensitive production Vercel variable `STAR_ORGANISATION_WORKER_SECRET`; never commit it or expose it to a browser. The existing server-side `RESEND_API_KEY` and `STAR_ENQUIRY_FROM` provide delivery. No service-role key is deployed to Vercel.

The minute cron job invokes the fixed production endpoint only when work is due. Jobs are claimed with SKIP LOCKED and a five-minute token lease. Immediately before each send the worker rechecks current access, verified recipient email, parent consent and unread state. Email contains a generic update notice and portal link only. Read alerts are suppressed; portal records remain available. Resend receipts are checked, and the stable delivery UUID is the provider idempotency key. Transient errors retry up to eight times with exponential backoff; permanent provider rejection is recorded failed. A crashed worker lease expires and can be recovered. The handler stops before its runtime deadline; unprocessed claims recover after the lease.

Monitoring (privileged SQL): group `star_private.org_deliveries` by status; investigate `failed` jobs/provider configuration without logging email addresses or message content. A sent row means accepted by the provider, not inbox delivery. Disable sending with `cron.unschedule('star-organisation-inbox-email')`; queued portal messages are retained. Roll back application to the preceding release without dropping the additive tables; disable cron if rolling back the handler. Rotate both Vault and Vercel credential together and redeploy.

Validation: `supabase/tests/organisation_inbox.sql` uses synthetic rollback-only fixtures and never invokes the provider. It covers anonymous/unverified denial, cross-organisation and coach isolation, direct-table denial, idempotency, personal unread state, automatic feedback/request/observation events, consent withdrawal, revoked memberships, paused organisations and send-time recipient checks. `node scripts/test-organisation-email.cjs` mocks all network delivery for both inbox audiences, receipts, retries, permanent failure and suppressed recipients. TypeScript and production build are required. No real test emails or usability tests.
